# 人工审批流程说明

本文件说明 06-Agent自建知识 中两条独立的审批通道，以及审批通过/驳回后
Agent 应该做什么。**这两条通道不是前后串联关系，不要混用。**

## 一、两条独立通道

### 通道 A：优化建议（`propose_optimization.py` → [04]优化建议）

审批对象：针对「流程/做法」的改进意见（比如"写入流程应该改成 XXX"）。

```
Agent 提交优化建议（scripts/propose_optimization.py）
    ↓ 状态标记为"待审批"
人工审核：
├── ✅ 通过 → 由人工手动调整对应 SOP/规范文档（在业务目录内完成）
│              Agent 不自动执行任何迁移动作，**不触发** migrate_to_business.py
├── ❌ 驳回 → 人工在索引表"状态"列 + 详情章节"状态"字段标注驳回原因
│              两处必须同步修改，返回给 Agent
└── 🔄 要求补充 → 标注补充要求，返回给 Agent 重新提交
```

### 通道 B：待人工审核（`write_pending_review.py` → [05]待人工审核）

审批对象：某条「知识内容」本身要不要转正进业务目录（01-05）。

```
Agent 提交转正申请（scripts/write_pending_review.py）
    ↓ 状态标记为"待审批"
人工审核：
├── ✅ 通过 → 在索引表该行"状态"列标记为"已审批"
│              Agent 据此调用 migrate_to_business.py（**唯一合法触发源**）
│              迁移完成后，源条目状态更新为"已合并至 XX"
├── ❌ 驳回 → 索引表"状态"列标注"已驳回"及原因
└── 🔄 要求补充 → 索引表"状态"列标注"需补充"，Agent 补充信息后重新提交
```

## 二、为什么要分成两条通道

- **优化建议**改的是"以后应该怎么做"（流程/规范/SOP），落地对象是文档本身的
  写作规则或操作步骤，跟"某条具体知识内容"无关。
- **待人工审核**改的是"这条已经验证过的知识该不该固化"，落地对象是把 06 目录
  里的一条记录复制/迁移到 01-05 业务目录，跟"流程怎么改"无关。

混用会导致 `migrate_to_business.py` 误读优化建议里的自由文本作为迁移目标，
产生错误的业务目录变更，这是**必须避免**的硬性风险。

## 三、审批状态取值约定

| 状态 | 含义 | 适用文档 |
|------|------|----------|
| 待审批 | 刚提交，等待人工处理 | 优化建议 / 待人工审核 |
| 已审批 | 人工确认通过，待人工审核文档专用，可触发迁移 | 待人工审核 |
| 已驳回 | 人工不同意，需说明原因 | 优化建议 / 待人工审核 |
| 需补充 | 信息不足，需 Agent 补充后重新提交 | 优化建议 / 待人工审核 |
| 已合并至 XX | 迁移完成后的终态，XX 为目标业务目录 | 待人工审核 |

Agent 在调用 `migrate_to_business.py` 之前，必须先读取 `[05]待人工审核`
的最新 XML，确认目标条目状态确实是"已审批"，否则拒绝执行迁移。
