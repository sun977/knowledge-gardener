# 知识库完整结构说明

供 Agent 在执行任何写入/迁移操作前，理解知识库各目录的边界、定位和读写权限。

## 一、六个一级目录

知识库根目录：`https://km.sankuai.com/collabpage/2775934808`

| 目录 | 定位 | 维护方式 |
|------|------|----------|
| 00-知识库元信息 | 知识库使用说明、版本日志 | 人工为主，Agent 仅追加版本日志行 |
| 01-05（业务目录，具体命名以线上为准） | 经人工审核确认的权威业务知识 | 人工维护，Agent 严格只读 |
| 06-Agent自建知识 | Agent 自主写入的学习日志/经验/踩坑/建议/待审核 | Agent 可自由读写 |

## 二、Agent 读写权限矩阵

| 目录 | Agent 读 | Agent 写 | 说明 |
|------|:--:|:--:|------|
| 00-知识库元信息 | ✅ | 仅追加版本日志行 | 不得修改历史行、不得改写他人维护的内容 |
| 01-05 业务目录 | ✅ | ❌ | **严格只读**。唯一的写入入口是 `migrate_to_business.py`，且必须先有人工审批 |
| 06-Agent自建知识 | ✅ | ✅ | 唯一可自由读写的区域，但仍需遵守 `references/writing-rules.md` 的格式规范 |

## 三、06-Agent自建知识 的 5 个固定子文档

以下 contentId 为线上真实值，已在 `lib/content_ids.py` 中定义为常量。
Agent **只能**对这 5 个 contentId 做追加写入，不得新建同类文档：

| 文档 | contentId | 结构 | 对应脚本 |
|------|-----------|------|----------|
| [01]学习日志 | 2780767955 | 索引表（日期/任务类型/反思摘要）+ 详情章节 | `write_learning_log.py` |
| [02]经验沉淀 | 2781086741 | 索引表（场景/经验摘要/验证次数/状态）+ 详情章节 | `write_experience.py` |
| [03]踩坑记录 | 2781216217 | 索引表（日期/踩坑场景/状态）+ 详情章节 | `write_pitfall.py` |
| [04]优化建议 | 2781276182 | 索引表（日期/优化目标/状态）+ 详情章节 | `propose_optimization.py` |
| [05]待人工审核 | 2781426045 | 纯索引表（日期/内容概要/目标合并目录/状态） | `write_pending_review.py` |

父目录 `06-Agent自建知识` 的 contentId 为 `2780936747`（`PARENT_CONTENT_ID`）。

## 四、目录层级关系图

```
00-知识库元信息（人工维护，Agent 仅追加版本日志）
01～05 业务目录（人工维护，Agent 只读）
    ↑
    │ migrate_to_business.py（唯一写入入口，需人工审批）
    │
06-Agent自建知识（Agent 自由读写，contentId=2780936747）
├── [01]学习日志       —— 每次任务结束后追写
├── [02]经验沉淀       —— Agent 主观判断某模式已反复验证有效后追写（无自动计数机制）
├── [03]踩坑记录       —— 遇到错误异常时追写
├── [04]优化建议       —— 发现流程可改进时提交（审批后由人工手动落地，不经过迁移脚本）
└── [05]待人工审核     —— 内容转正申请（审批后触发 migrate_to_business.py）
```

## 五、为什么这样设计（读写分离的原因）

- **业务目录（01-05）是权威知识源**，如果 Agent 可以直接改写，一旦 Agent
  产生幻觉或错误推断，会直接污染团队依赖的权威知识，且难以追溯。
- **06 目录是 Agent 的"草稿本"**，允许自由读写、允许试错，但不直接对外权威，
  这样即使内容有误，影响范围也被限制在 06 目录内。
- **迁移（06 → 01-05）必须经过人工审批**，是从"草稿"到"权威"之间唯一的桥梁，
  这是保证知识库质量的核心机制，不可绕过。

## 六、结构选型说明（索引表 + 详情章节）

06 目录下 4 个文档（[05]待人工审核除外）采用「索引表 + 详情章节」复合结构，
而不是纯表格或纯章节。原因：踩坑记录的错误信息、优化建议的风险评估等字段是
长文本/多行内容，学城表格单元格窄小（历史遗留 `colwidth=68`），塞长文本会
导致阅读体验极差；但纯章节又丢失了快速扫描历史记录的能力。详见
`references/writing-rules.md` 第一节。
