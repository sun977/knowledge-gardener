# 写入格式与质量规范

本文件供 Agent 在调用任意 `scripts/write_*.py` / `scripts/propose_optimization.py`
之前阅读，确保写入学城知识库的内容格式统一、质量可靠。

## 一、结构规范

06-Agent自建知识 下 5 个子文档统一采用「索引表 + 详情章节」复合结构（`[05]待人工审核`
除外，仅索引表）：

- **索引表**：放短字段，用于快速扫描定位历史记录
- **详情章节**：放长字段（错误堆栈、风险评估等多行内容），标题格式固定为
  `## 日期 | 场景` 或 `## 场景`（视文档而定，见下方各文档说明）

写入时**索引行与详情章节必须同时生成、同时插入**，缺一不可，保持两者一一对应。

## 二、学城 XML 格式要求

- 使用学城富文本原生节点（`p` / `h1~h6` / `ul` / `ol` / `table`），**禁止**使用
  `<km-markdown>` 标签直接塞 Markdown 文本
- 表格必须有表头行（`<tr>` 中带表头样式的首行）
- 新增 `<tr>` 需继承已有列的结构属性；索引表历史列可能带 `colwidth`，新行沿用即可，
  不强制新增 `colwidth`
- **必须保留**所有原有节点的 `nodeId`；新增节点可以省略 `nodeId`（学城会自动生成）
- **禁止**引入 `div` / `section` / `thead` / `tbody` 等布局性 HTML 标签

## 三、各文档格式细则

| 文档 | 索引表标题格式 | 详情章节标题格式 |
|------|----------------|------------------|
| [01]学习日志 | 日期 / 任务类型 / 反思摘要 | `## {日期} \| {任务类型}` |
| [02]经验沉淀 | 场景 / 经验摘要 / 验证次数 / 状态 | `## {场景}` |
| [03]踩坑记录 | 日期 / 踩坑场景 / 状态 | `## {日期} \| {场景}` |
| [04]优化建议 | 日期 / 优化目标 / 状态 | `## {日期} \| {优化目标}` |
| [05]待人工审核 | 日期 / 内容概要 / 目标合并目录 / 状态 | 无 |

> 索引行中的关键字段（场景 / 优化目标等）**必须与详情章节标题完全一致**，因为学城
> 不支持内部锚点跳转，人工与 Agent 只能靠文字匹配定位对应的详情章节。

## 四、质量红线（不可协商）

- **禁止编造数据**：所有数值必须来自真实数据源（日志、报错信息、实际验证结果）
- **禁止无来源的相对性判断**："异常 / 升高 / 下降"必须附带基线值和变化率
- **禁止四舍五入改写原始数值**：`error_msg` 等原始报错必须原样保留（用代码块承载）
- **禁止将 AI 推断与数据源结论混为一谈**：推断内容需明确标注"推测"

## 五、每条记录必须包含

- 日期戳（格式 `YYYY-MM-DD`，学习日志/踩坑记录/优化建议/待人工审核索引行的首列）
- 至少一项可验证的具体内容（不能是空话套话）
- 需要审批的记录（优化建议、待人工审核）必须包含"状态"字段，初始值为"待审批"

## 六、内容质量原则

宁可少写一条高质量记录，不写十条低质量记录。写入前请再读一遍
`references/quality-checklist.md` 做最终自检。
