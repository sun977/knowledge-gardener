# LingCat Knowledge Gardener 用户使用手册

面向**日常使用这个 skill 的你**，不讲代码架构、不讲设计原理，只讲：
遇到什么场景、该说什么话、Agent 会做什么、你需要做什么。

> 想了解"为什么这么设计"，请看仓库根目录的 `README.md`；本手册只讲"怎么用"。

---

## 一、这个工具能帮你做什么

简单说：**让 Agent 自己记笔记，而不是每次都要你去手动整理**。

Agent 在帮你做审计、排查、分析类任务的过程中，会积累一些值得记住的东西——
踩过的坑、总结出的好方法、发现的流程问题。这个 skill 让 Agent 能把这些内容
自动整理好格式，写进学城知识库，下次不管是你还是别的同事用 Agent 处理类似
任务，都能直接查到这些经验。

你全程不需要手写一个字进学城，唯一需要你做的是：**在关键节点点头确认**。

---

## 二、五个场景，你会遇到什么

### 场景 1：任务做完了，Agent 主动记笔记（不用你管）

每次 Agent 帮你完成一个任务（比如一次审计排查、一次数据分析）后，
它会**自动**把这次任务的过程写一条学习日志，不需要你说任何话，也不需要确认。

你会看到类似这样的汇报：
> "本次排查过程已写入学习日志。"

**你不需要做任何事**，纯粹是 Agent 自己的记录习惯。

---

### 场景 2：Agent 踩坑了，自动记下来（不用你管）

如果 Agent 在执行任务过程中遇到了报错、异常，解决之后，它同样会**自动**
把这次踩坑的场景、报错信息、原因、解决办法记下来，不用你确认。

**你不需要做任何事**。

---

### 场景 3：Agent 觉得某个操作方法值得沉淀成经验（需要你说"好"）

如果 Agent 发现自己反复用某个方法解决问题、效果都不错，它会**主动来问你**：

> "我发现 XX 这个操作方式已经验证过好几次都有效，要不要把它沉淀成一条经验？"

**你需要做的**：回答"好"或者"不用"。
- 只有你明确同意后，Agent 才会真正写入
- 如果同一个方法之前已经写过一次经验，Agent 会告诉你"这次是第 N 次验证"，
  只更新验证次数，不会重复写一条一样的内容

> 💡 这里**没有一个固定的"用够 3 次就自动写"的规则**——完全是 Agent 根据
> 实际情况主观判断"这个方法是不是已经验证得比较扎实了"，然后来问你，
> 由你最终拍板。

---

### 场景 4：Agent 发现某个流程可以改进（需要你说"好"，之后还要你自己动手改）

如果 Agent 在做事过程中发现"这个流程/规范其实可以优化"，它会来问你：

> "我发现 XX 流程可以这样改进……要不要我把这条建议记录下来？"

**你需要做的分两步**：
1. 先决定"记不记"——同意的话 Agent 会把建议连同现状、改进方案、风险评估
   一起写进「优化建议」文档，状态标记为"待审批"
2. 之后你要抽空去学城打开这份文档，**自己决定要不要采纳**：
   - 采纳的话，你需要**自己动手**去改对应的规范/流程文档（这一步 Agent
     不会代劳，因为具体怎么改是需要人工判断的）
   - 不采纳的话，在文档里标注"已驳回"及原因即可

> ⚠️ 注意：这里的"优化建议"改的是**以后应该怎么做**，跟下面场景 5 的
> "内容转正"是两件完全不同的事，不要混。

---

### 场景 5：Agent 认为某条经验已经很成熟，建议转正为团队权威知识（需要你审批两次）

当某条经验或踩坑记录已经被反复验证、Agent 觉得它足够可靠、值得作为
团队标准知识长期保留时，会来问你：

> "这条经验已经验证了 N 次，我觉得可以转正到业务知识库了，要不要提交审核？"

**你需要做的分两步**：

**第一步：同意提交** → Agent 会把这条内容写进「待人工审核」文档，状态是
"待审批"。

**第二步：你去学城正式审批** → 打开「待人工审核」文档，找到那一行，确认
内容确实值得转正后，**把状态列改成"已审批"**（这一步必须你手动改，
Agent 不会替你改这个状态）。改完告诉 Agent"可以合并了"，Agent 才会真正
把内容搬进团队的正式知识库目录。

如果你在文档里看到状态还是"待审批"，说明这条还**没有被处理**，Agent
不会擅自帮你做决定。

## 三、你会用到的四个"人工动作"清单

| 你要做的事 | 在哪做 | 什么时候做 |
|---|---|---|
| 回答"要不要写经验" | 直接在对话里回复 Agent | Agent 主动询问时 |
| 决定"优化建议"要不要采纳 + 自己动手改规范文档 | 学城「[04]优化建议」文档 | 你有空的时候，定期看看 |
| 把「待人工审核」条目状态改成"已审批" | 学城「[05]待人工审核」文档 | 决定同意转正时 |
| 告诉 Agent "可以合并了" | 直接在对话里说 | 上一步改完状态之后 |

## 四、几个你可能会问的问题

**Q：我什么都不用管，Agent 会自己把所有东西都写进团队知识库吗？**

不会。Agent 只能自由写它自己的"草稿区"（06-Agent自建知识），团队大家
共用的正式知识库（01-05 业务目录）它没有权限直接改，唯一的入口是你在
场景 5 里亲自审批"已审批"之后才会触发。这是故意设计成这样的，避免
Agent 记错东西污染大家都在用的权威内容。

**Q：Agent 问我"要不要沉淀经验"，我不想每次都被问怎么办？**

直接告诉 Agent"这次不用，你自己判断就行，不用每次都问我"——但请注意，
写经验/提优化建议/转正申请这三件事，都是刻意设计成必须你确认的，
如果不问就直接写，一旦 Agent 判断错了会直接污染知识库内容，所以目前
不支持完全跳过确认。

**Q：优化建议提交后，是不是也会自动改到规范文档里？**

不会。优化建议只是"记录一个想法"，改不改、怎么改，都需要你自己去看、
自己去动手改对应文档。Agent 不会替你去改团队的 SOP/规范。

**Q：转正审批时，如果我改错了状态怎么办？**

只要你没有改成"已审批"这三个字，Agent 就不会执行合并动作，改成别的
任何状态（比如"已驳回"、"需补充"）都是安全的，Agent 会拒绝合并并
告诉你原因。

**Q：我能看到 Agent 目前记了哪些经验/踩坑吗？**

可以，直接去学城对应的文档看就行：
- 学习日志、经验沉淀、踩坑记录、优化建议、待人工审核，都在
  `06-Agent自建知识` 这个目录下，五份独立的文档，随时可以打开查看，
  跟看普通学城文档一样，不需要任何特殊操作。

---

## 五、一句话总结

**Agent 自动记学习日志和踩坑记录，不用你管；想沉淀经验、提优化建议、
申请内容转正这三件事都要先问你同意；优化建议采纳后要你自己动手改文档；
内容转正需要你亲自在学城把状态改成"已审批"，Agent 才会真正执行合并。**
