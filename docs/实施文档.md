## 一、架构设计

### 1.1 核心原则

**每个 Script 只做一件事：构造数据。写入流程统一走公共写入库。**

这个原则消除了 6 个 Script 中重复的 8 步写入流程，是本项目最重要的架构决策。

### 1.3 为什么用 Jinja2？

- **模板功能完整**：支持 `if/else`、`for` 循环、模板继承
- **Python 标准库兼容**：`pip install jinja2` 即可
- **学习曲线低**：语法简单，类似 HTML + 变量
- **安全性**：沙箱模式防止模板注入

**不选的理由**：
- `string.Template`：功能太弱，不支持条件判断
- Mustache：非 Python 原生，需要额外依赖

### 1.4 公共工具库 `lib/writer.py`

#### 职责

`writer.py` 只负责**模板渲染**和**质量自检**，**不包含任何学城交互逻辑**。

学城操作（`getDocumentXml` → 修改 XML → `updateDocumentByXml`）**全部由 Agent 调用 citadel CLI 完成**。

> **核心原则**：Script 是工具，Agent 是指挥者。Script 只管构造数据，Agent 负责协调所有操作。

#### 接口定义

> **关键变化（v1.1）**：线上文档是「索引表 + 详情章节」复合结构（详见设计文档 v1.1 第三节），因此 `render_template` 不再渲染单一内容，而是**同时渲染两段**：`row`（追加到索引表 `<tbody>` 末尾的一个 `<tr>`）和 `detail`（追加到「详情记录」标题下方的一个 `## 标题` 章节）。`[05]待人工审核` 没有详情章节，只渲染 `row`。

```python
from jinja2 import Environment, FileSystemLoader
from pathlib import Path

TEMPLATE_DIR = Path(__file__).parent.parent / "assets" / "templates"

class KnowledgeWriter:
    def __init__(self):
        """
        初始化写入库（模板加载器）
        
        学城交互由 Agent 调用 citadel CLI 完成，不需要 API 客户端。
        """
        self.env = Environment(
            loader=FileSystemLoader(TEMPLATE_DIR),
            keep_trailing_newline=True
        )
    
    def render_entry(self, doc_key: str, context: dict) -> dict:
        """
        渲染一条完整记录（索引行 + 详情章节）
        
        Args:
            doc_key: 文档标识（如 'learning-log' / 'pitfall' / 'experience' / 'optimization' / 'pending-review'）
            context: 模板上下文变量（字典）
        
        Returns:
            {
                'row': '<tr>...</tr>' 或对应 Markdown 表格行,       # 插入索引表
                'detail': '## 标题\n...' 或 None（pending-review 无详情章节）  # 插入详情记录章节
            }
        """
        row_template = self.env.get_template(f"{doc_key}-row.j2")
        row = row_template.render(**context)
        
        detail = None
        if doc_key != 'pending-review':
            detail_template = self.env.get_template(f"{doc_key}-detail.j2")
            detail = detail_template.render(**context)
        
        return {'row': row, 'detail': detail}
    
    def quality_check(self, content_type: str, context: dict) -> list:
        """
        质量自检（读取 references/quality-checklist.md 逐项检查）
        
        Returns:
            失败的检查项列表（空列表表示通过）
        """
        errors = []
        
        # 1. 内容不为空
        for key, value in context.items():
            if isinstance(value, str) and value.strip():
                continue
            if isinstance(value, list) and value:
                continue
        
        # 2. 日期格式检查（YYYY-MM-DD）
        date = context.get('date', '')
        if date and len(date) != 10 or date[4] != '-' or date[7] != '-':
            errors.append('日期格式不正确，应为 YYYY-MM-DD')
        
        # 3. 根据内容类型做特定检查
        if content_type == 'learning_log':
            if not context.get('task_summary', '').strip():
                errors.append('task_summary 不能为空')
            improvements = context.get('improvements', [])
            if not improvements or all(not i.strip() for i in improvements):
                errors.append('improvements 至少列出 1 项（即使没有也要写"暂无"）')
        
        return errors
```

#### 每个 Script 的调用方式

```python
# scripts/write_learning_log.py
from lib.writer import KnowledgeWriter
from lib.content_ids import LEARNING_LOG_CONTENT_ID

def main(task_type, task_summary, execution_review, good_points, improvements, linked_docs):
    writer = KnowledgeWriter()
    
    # 1. 构造数据
    context = {
        'date': __import__('datetime').datetime.now().strftime('%Y-%m-%d'),
        'task_type': task_type,
        'task_summary': task_summary,
        'execution_review': execution_review,
        'good_points': good_points,
        'improvements': improvements,
        'linked_docs': linked_docs or ['暂无']
    }
    
    # 2. 质量自检
    errors = writer.quality_check('learning_log', context)
    if errors:
        return {'success': False, 'message': f'质量自检失败: {errors}'}
    
    # 3. 渲染模板（同时得到索引行和详情章节两段内容）
    entry = writer.render_entry('learning-log', context)
    
    # 4. 返回渲染结果（给 Agent）
    # Agent 负责调用 citadel CLI，把 entry['row'] 插入索引表末尾，把 entry['detail'] 插入详情记录章节末尾
    return {
        'success': True,
        'content_id': LEARNING_LOG_CONTENT_ID,
        'row': entry['row'],
        'detail': entry['detail'],
        'message': '模板渲染完成，请调用 citadel 同时写入索引行和详情章节'
    }
```

#### Agent 操作流程

```
Agent 收到 Script 返回的 {row, detail} 后：

1. 调用 citadel CLI：

3. 调用 citadel CLI：
```

## 三、Jinja2 模板定义

### 3.1 模板加载器 `lib/jinja2_templates.py`

```python
from jinja2 import Environment, FileSystemLoader, TemplateNotFound
from pathlib import Path

class Jinja2TemplateLoader:
    def __init__(self):
        # 模板目录：assets/templates/
        self.template_dir = Path(__file__).parent.parent / 'assets' / 'templates'
        self.env = Environment(
            loader=FileSystemLoader(self.template_dir),
            keep_trailing_newline=True
        )
    
    def load(self, template_name: str):
        """加载模板
        
        Args:
            template_name: 模板文件名（如 'learning-log-row.j2'）
        
        Returns:
            jinja2.Template 对象
        """
        try:
            return self.env.get_template(template_name)
        except TemplateNotFound:
            raise FileNotFoundError(f"模板不存在: {template_name}")
```

> **命名规则**：每个文档对应一对模板 —— `{doc_key}-row.j2`（索引行，渲染为一行 Markdown 表格行，对应回传 XML 中的一个 `<tr>`）与 `{doc_key}-detail.j2`（详情章节，渲染为 `## 标题` 开头的一个章节）。`pending-review` 只有 `-row.j2`。

## 四、错误处理方案

### 4.1 错误类型定义

```python
class KnowledgeGardenerError(Exception):
    """基类错误"""
    pass

class WriterError(KnowledgeGardenerError):
    """写入错误"""
    def __init__(self, message, step=None):
        self.step = step  # 出错步骤（如 'getDocumentXml', 'updateDocumentByXml'）
        super().__init__(f"{step}: {message}" if step else message)

class TemplateError(WriterError):
    """模板渲染错误"""
    pass

class ApiError(WriterError):
    """API 调用错误"""
    def __init__(self, message, status_code=None):
        self.status_code = status_code
        super().__init__(message)

class QualityCheckError(WriterError):
    """质量自检失败"""
    pass
```

### 4.2 错误处理策略

| 错误类型 | 处理方式 | 是否重试 |
|----------|----------|----------|
| API 超时 | 重试 3 次（指数退避） | 是 |
| API 认证失败 | 直接报错，不重试 | 否 |
| 模板渲染失败 | 直接报错，记录模板名和上下文 | 否 |
| 质量自检失败 | 直接报错，列出失败项 | 否 |
| XML 解析失败 | 报错，保留原始内容 | 否 |

### 4.3 重试逻辑

```python
import time
from functools import wraps

def retry(max_attempts=3, backoff_factor=2):
    """指数退避重试装饰器"""
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except ApiError as e:
                    if attempt == max_attempts:
                        raise
                    wait_time = backoff_factor ** attempt
                    time.sleep(wait_time)
        return wrapper
    return decorator
```

### 4.4 每个 Script 的错误处理

```python
# scripts/write_learning_log.py
from lib.writer import KnowledgeWriter, QualityCheckError, ApiError
from lib.content_ids import LEARNING_LOG_CONTENT_ID

def main(task_type, task_summary, execution_review, good_points, improvements, linked_docs):
    writer = KnowledgeWriter()
    
    try:
        # 1. 构造数据
        context = {
            'date': datetime.now().strftime('%Y-%m-%d'),
            'task_type': task_type,
            'task_summary': task_summary,
            'execution_review': execution_review,
            'good_points': good_points,
            'improvements': improvements,
            'linked_docs': linked_docs
        }
        
        # 2. 质量自检
        errors = writer.quality_check('learning_log', context)
        if errors:
            raise QualityCheckError(str(errors))
        
        # 3. 同时渲染索引行与详情章节
        entry = writer.render_entry('learning-log', context)
        
        return {
            'success': True,
            'content_id': LEARNING_LOG_CONTENT_ID,
            'row': entry['row'],
            'detail': entry['detail']
        }
    
    except QualityCheckError as e:
        # 质量自检失败，返回详细错误信息
        return {
            'success': False,
            'message': f'质量自检失败: {e}',
            'retryable': True
        }
    
    except ApiError as e:
        # API 调用失败，可能重试后成功
        return {
            'success': False,
            'message': f'API 调用失败: {e}',
            'retryable': True
        }
    
    except Exception as e:
        # 未知错误，记录日志
        return {
            'success': False,
            'message': f'未知错误: {e}',
            'retryable': False
        }
```

> 注意：上述 `writer.write(template_name=...)` 的旧用法已废弃，统一改为 `writer.render_entry(doc_key=...)`，同时返回 `row` 与 `detail` 两段，由 Agent 负责同步写入两处。

## 七、关键设计决策记录

### 决策 1：经验沉淀改为手动触发

**决策**：取消"≥3 次自动检测"，改为 Agent 主动建议 + 用户确认

**理由**：
- Agent 会话无状态，无法持久化计数
- "同类模式"没有可靠的判断标准
- 即使用户建议，用户也不一定认可

**替代方案**：Agent 在学习日志完成后说"建议写一条经验"，用户确认后才触发

### 决策 2：公共写入库抽取

**决策**：所有写入操作统一走 `lib/writer.py`

**理由**：
- 6 个 Script 共享 8 步写入流程，重复代码太多
- 统一入口便于维护和扩展
- 符合 DRY 原则

### 决策 3：模板使用 Jinja2

**决策**：统一使用 Jinja2 作为模板引擎

**理由**：
- 功能完整，支持 `if/else`、`for` 循环
- Python 原生，学习曲线低
- 安全性高（沙箱模式）

### 决策 4：健康巡检先砍掉"矛盾检测"

**决策**：v1.0 不做语义级矛盾检测

**理由**：
- 复杂度与收益不匹配
- 当前阶段做不了可靠的语义推理
- 留到 v2.0 再考虑
