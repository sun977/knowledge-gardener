## 一、概述

### 1.1 定位

灵猫知识库自治维护工具。Agent 在执行审计任务过程中及任务结束后，自动将经验、反思、踩坑记录写入学城知识库，实现知识库的"Agent自成长"。

### 1.2 核心理念

- **三不原则**：不编数据、不跳步、不静默覆盖
- **读写分离**：Agent 可自由读写 06-Agent自建知识 目录；业务目录（01-05）严格只读，进入业务目录必须经过人工审批

### 1.3 核心价值

| 价值点 | 说明 |
|--------|------|
| 经验资产化 | 将 Agent 每次任务的实践经验沉淀为可复用知识 |
| 错误可追溯 | 踩坑记录使同类错误不再重复发生 |
| 流程持续优化 | Agent 自主提出优化建议，经人工审批后升级为标准流程 |
| 知识库健康度 | 定期巡检，识别过期、矛盾、冗余内容 |

## 三、SKILL.md 设计

### 3.1 Frontmatter

```yaml
---
name: lingcat-knowledge-gardener
description: 灵猫知识库自治维护工具。用于Agent自主更新学城知识库中的自建知识目录（06-Agent自建知识），包括学习日志、经验沉淀、踩坑记录、优化建议和待人工审核。触发条件：1) Agent完成审计任务后需要记录反思；2) Agent遇到错误或异常需要记录踩坑；3) Agent发现可优化的流程或规范；4) 定期巡检知识库健康度；5) 积累足够经验后提出内容转正申请。不触发：直接修改业务目录（01-05）；不触发：用户主动咨询知识库使用方式（那是00-知识库元信息的活）。
---
```

### 3.2 Body 核心流程

#### 路由决策树

```
用户指令 / 事件触发
    ↓
判断意图：
├── "写学习日志" / 任务结束 ────→ 调用 scripts/write_learning_log.py
├── "写经验沉淀" / Agent判断某操作模式已多次验证有效（需用户确认）─→ 调用 scripts/write_experience.py
├── "写踩坑记录" / 遇到错误异常 ──→ 调用 scripts/write_pitfall.py
├── "提优化建议" / 发现流程可改进空间 ─→ 调用 scripts/propose_optimization.py
├── "提内容转正申请" / 内容已验证充分 ─→ 调用 scripts/write_pending_review.py
├── "巡检知识库" / 定时/手动触发 ─→ 调用 scripts/health_check.py
└── "合并到业务目录" / 待审核内容人工确认通过 → 调用 scripts/migrate_to_business.py（输入源仅为 [05]待人工审核）
```

#### 目标文档 contentId（真实值，固定常量）

06-Agent自建知识（父目录 contentId：2780936747）下 5 个子文档已在线上建好固定表结构，Agent 只能对以下 5 个 contentId 做追加写入，不得新建同类文档：

| 文档 | contentId | 结构 |
|------|-----------|------|
| [01]学习日志 | 2780767955 | 索引表（日期/任务类型/反思摘要）+ 详情章节 |
| [02]经验沉淀 | 2781086741 | 索引表（场景/经验摘要/验证次数/状态）+ 详情章节 |
| [03]踩坑记录 | 2781216217 | 索引表（日期/踩坑场景/状态）+ 详情章节 |
| [04]优化建议 | 2781276182 | 索引表（日期/优化目标/状态）+ 详情章节 |
| [05]待人工审核 | 2781426045 | 纯索引表（日期/内容概要/目标合并目录/状态） |

> **为什么是「索引表 + 详情章节」而不是纯表格或纯章节**：踩坑记录的错误信息、优化建议的风险评估等字段是长文本/多行内容，学城表格单元格窄小（历史遗留 `colwidth=68`），塞长文本会导致阅读体验极差；但纯章节又丢失了快速扫描历史记录的能力。故统一采用复合结构：**索引表**放短字段用于扫描定位，**详情章节**（`## 日期 | 场景` 或 `## 场景`）放长字段承载完整内容。`[05]待人工审核` 字段全部短小，无需详情章节，保留纯表格。

#### 通用写入流程（所有写入操作共享，除 05 待人工审核外）

1. 确定目标文档（contentId，见上表，硬编码在脚本常量中）
2. 拉取当前文档内容（getDocumentXml → 保存本地）
3. 读取 references/writing-rules.md 获取格式规范
4. 按模板渲染出两段内容：① 索引表新增一行（`<tr>`，短字段） ② 详情章节新增一个章节块（`## 标题` + 完整字段）
5. 运行 references/quality-checklist.md 自检
6. 更新知识库元信息版本日志
7. 回写文档（updateDocumentByXml，同时插入①②两处）
8. 确认写入成功

`[05]待人工审核` 只有索引表，跳过步骤 4 中的详情章节部分，直接追加一行。

#### 各子流程说明

| 子流程 | 触发条件 | 操作 | 人工介入 |
|--------|----------|------|----------|
| 学习日志 | 每次任务结束 | 追写反思记录 | 无需 |
| 经验沉淀 | Agent 主观判断某模式已反复验证有效（无自动计数，见决策1） | 归纳总结有效操作 | 定期review |
| 踩坑记录 | 遇到错误/异常 | 记录错误信息+解决方案 | 无需 |
| 优化建议 | 经验+踩坑中发现改进点 | 提交流程/规范改进建议（含风险评估） | 必须审批 |
| 待人工审核 | Agent 认为某条内容已验证充分，值得转正进业务目录 | 提交内容转正申请 | 必须审批 |
| 健康巡检 | 定时（建议每周） | 检查内容一致性、过期标记、冗余 | 定期review |

> ⚠️ **优化建议 与 待人工审核 是两条独立通道，不是前后串联关系**：
> - **优化建议**：针对「流程/做法」的改进意见，审批通过后由人工手动调整对应 SOP/规范文档（该调整动作在业务目录内完成，不经过 `migrate_to_business.py`）
> - **待人工审核**：针对某条「知识内容」本身要不要转正进业务目录（01-05）的申请，审批通过后才执行 `migrate_to_business.py`
> `migrate_to_business.py` 的唯一合法输入源是 `[05]待人工审核`，不是 `[04]优化建议`。

## 四、Scripts 设计

### 4.1 write_learning_log.py

**用途**：在 📝 学习日志 文档中追写一条新的学习记录

**输入参数**：

| 参数 | 说明 |
|------|------|
| task_type | 任务类型（审计排查/数据分析/报告生成/系统操作） |
| task_summary | 任务概要（1-2句） |
| execution_review | 执行过程回顾 |
| good_points | 做得好的地方（列表） |
| improvements | 可以改进的地方（列表） |
| linked_docs | 关联文档链接（可选） |

**输出**：写入成功后返回新的 contentId 和链接

**质量自检**：

- 每条记录必须包含 task_summary（不能为空）
- improvements 至少列出1项（即使没有也要写"暂无"）
- 如果 linked_docs 存在，验证链接可达性

### 4.2 write_experience.py

**用途**：在 🧪 经验沉淀 文档中追写一条经验记录

**触发条件**：同一类模式在 write_learning_log 中出现 ≥ 3 次

**输入参数**：

| 参数 | 说明 |
|------|------|
| scene | 适用场景描述 |
| steps | 标准操作步骤 |
| why_works | 为什么有效 |
| conditions | 适用边界条件 |
| source_logs | 来源学习日志的链接列表 |

**输出**：写入成功后返回新的 contentId 和链接

### 4.3 write_pitfall.py

**用途**：在 ⚠️ 踩坑记录 文档中追写一条踩坑记录

**输入参数**：

| 参数 | 说明 |
|------|------|
| scene | 错误场景 |
| error_msg | 错误信息（原始报错） |
| root_cause | 原因分析 |
| solution | 解决方案 |
| prevention | 预防建议 |
| frequency | 该类型错误出现次数（自动计数） |

**特殊逻辑**：

- 同一类坑出现 ≥ 3 次时，自动标记为"高频坑"
- 高频坑自动触发 propose_optimization.py

### 4.4 propose_optimization.py

**用途**：在 💡 优化建议 文档中提交一条优化建议

**触发条件**：

- 经验沉淀中发现流程可优化
- 踩坑记录中高频坑暴露系统性问题
- Agent 主动发现改进点

**输入参数**：

| 参数 | 说明 |
|------|------|
| target | 优化目标（指向哪个业务目录/文档） |
| current | 当前做法 |
| proposed | 建议做法 |
| expected_benefit | 预期收益（量化优先） |
| risk_assessment | 风险评估 |
| evidence | 支撑依据（经验/踩坑记录链接） |

**审批门控**：

- 提交后状态标记为 待审批
- 审批通过后，由人工手动将建议落地到对应业务目录/SOP 文档（Agent 不自动执行，`propose_optimization.py` 不触发 migrate_to_business.py）

### 4.5 write_pending_review.py

**用途**：在 🔖 待人工审核 文档中提交一条"内容转正"申请

**触发条件**：

- 经验沉淀中某条记录经过多次验证，Agent 认为已具备转正为业务知识的成熟度
- 踩坑记录中的高频坑，经验证解决方案稳定有效
- Agent 主动判断某条自建知识值得进入业务目录（01-05）

**输入参数**：

| 参数 | 说明 |
|------|------|
| content_summary | 内容概要（要转正的知识点） |
| target_dir | 目标合并目录（01-05 中的某一个） |
| source_link | 来源记录链接（经验沉淀/踩坑记录中的具体条目） |

**输出**：写入成功后返回新的 contentId 和链接

**审批门控**：

- 提交后状态标记为"待审批"
- 必须人工确认后才能执行 `migrate_to_business.py`（唯一合法触发源）

### 4.6 health_check.py

**用途**：知识库健康度巡检

**检查项**：

| 检查项 | 说明 | 严重度 |
|--------|------|--------|
| 内容过期 | 版本日志超过30天未更新 | 警告 |
| 关键词失效 | 索引表中的路径对应文档不存在 | 错误 |
| 冗余检测 | 多个文档描述同一内容 | 警告 |
| 矛盾检测 | 两个文档对同一规则描述不一致 | 错误 |
| 覆盖率 | 02-05目录下待补充项是否超过60天 | 警告 |
| 待审核积压 | 待人工审核超过14天未处理 | 警告 |

**输出**：生成巡检报告，写入学习日志并通知人工

### 4.7 migrate_to_business.py

**用途**：将人工审批通过的待转正内容合并到业务目录

**前提**：人工在 🔖 待人工审核 文档中确认（标记为"已审批/已合并"）。**注意：输入源是 `[05]待人工审核`，不是 `[04]优化建议`**。

**流程**：

1. 读取待迁移内容
2. 确认目标业务目录（01-05）的子文档列表
3. 在目标目录下创建/更新对应文档
4. 在源文档标记"已合并至 XX"
5. 更新知识库元信息版本日志

**安全规则**：

- 必须读取 references/approval-workflow.md 确认审批状态
- 合并前做 diff 比对
- 合并后保留源文档（不删除）

## 五、References 设计

### 5.1 kb-structure.md

知识库完整结构说明，供 Agent 理解各目录的边界和用途。

**内容**：

- 六个一级目录的定位和使用方式
- Agent 读写权限矩阵
- 目录层级关系图

### 5.2 writing-rules.md

内容格式与质量规范。

**格式要求**：

- 使用学城富文本原生节点（p/h1~h6/ul/ol/table），禁止 `<km-markdown>`
- 表格必须有表头行
- 每条记录必须有日期戳
- 数值必须有来源标注

**质量红线**：

- 禁止编造数据（所有数值必须来自真实数据源）
- 禁止无来源的相对性判断（"异常/升高/下降"必须附带基线值和变化率）
- 禁止四舍五入改写原始数值
- 禁止将 AI 推断与数据源结论混为一谈

### 5.3 quality-checklist.md

写入前质量自检清单（每次调用脚本前必须过一遍）：

- [ ] 内容不为空
- [ ] 日期格式正确（YYYY-MM-DD）
- [ ] 所有数值有来源标注
- [ ] 相对性判断附带基线值
- [ ] 与现有内容无矛盾（检查同目录其他记录）
- [ ] 格式符合模板规范
- [ ] 链接可达性验证（如有）

### 5.4 approval-workflow.md

人工审批流程说明：

```
Agent 提交优化建议
    ↓ 标记状态为"待审批"
人工审核：
├── ✅ 确认合并 → 执行 migrate_to_business.py
├── ❌ 驳回 → 标注驳回原因，返回给 Agent
└── 🔄 要求补充 → 标注补充要求，返回给 Agent 重新提交
```

## 六、Assets 模板设计

> **每个文档（除待人工审核外）对应两份模板**：一份渲染「索引表新增的一行」，一份渲染「详情记录追加的一个章节」。写入时两者必须同时生成并同时插入文档，保持索引表与详情章节一一对应。

```

**详情章节**（插入「详情记录」标题下方）：

```markdown

**任务概要**：{{task_summary}}

**执行回顾**：
{{execution_review}}

**做得好的**：
- {{good_point_1}}
- {{good_point_2}}

**可以改进的**：
- {{improvement_1}}
- {{improvement_2}}

**关联文档**：{{linked_docs}}
```

### 6.2 经验沉淀模板 (assets/templates/experience.md)

**索引行**：

```markdown
| {{scene}} | {{summary}} | {{count}} | {{status}} |
```

**详情章节**：

```markdown
## {{scene}}

**适用场景**：{{scene}}

**操作步骤**：
1. {{step_1}}
2. {{step_2}}
3. {{step_3}}

**为什么有效**：{{why_works}}

```markdown

​```

```markdown

**预期收益**：

## 七、集成设计

### 7.1 与灵猫Agent的关系

```
灵猫Agent (主对话)
    │
    ├── 执行审计任务 ──→ 调用 bi-query-sql / bi-analysis-moshu / dsp-risk-audit 等
    │                       │
    │                       ↓ 任务完成
    │                   自动调用 lingcat-knowledge-gardener
    │                       │
    │                       ├── write_learning_log.py
    │                       ├── write_pitfall.py（如有错误）
    │                       └── write_experience.py（如模式重复）
    │
    ├── 定期巡检 ──→ health_check.py
    │
    └── [05]待人工审核人工确认通过后 ──→ migrate_to_business.py（不涉及 [04]优化建议）
```

### 7.2 与知识库元信息的联动

每次写入操作后，自动更新 00-知识库元信息的版本日志。插入时遵循该表已有列顺序（版本/日期/变更内容/维护人）追加一行，不改动历史行，不与人工维护记录混淆（维护人列标注为 `Agent` 以与人工区分）：

| v2.1 | YYYY-MM-DD | [Agent] 学习日志：XX任务反思；踩坑记录：XX错误 | Agent |
|------|------------|------------------------------------------------|-------|

### 7.3 与 SOUL.md 的配合

在灵猫Agent的 SOUL.md 中增加以下规则，确保 Agent 主动使用 knowledge-gardener：

```markdown
## 知识库自治

1. 每次任务结束后，调用 knowledge-gardener 写学习日志
2. 遇到错误或异常时，调用 knowledge-gardener 写踩坑记录
3. 发现流程可优化时，调用 knowledge-gardener 提优化建议
4. 发现某条自建知识已验证充分、值得转正时，调用 knowledge-gardener 提交待人工审核申请
5. 不直接修改 01-05 业务目录，所有变更必须通过 06 目录 + 人工审批
```

## 十、注意事项

- 学城文档编辑必须走 XML 路径：getDocumentXml → 修改 → updateDocumentByXml，禁止用简化版 Markdown 直接回写
- 保留已有节点的 nodeId：已有节点的 nodeId 必须保留，新增节点可省略
- 禁止引入禁止标签：不引入 div/section/thead/tbody 等 HTML 布局标签
- 内容质量先于数量：宁可少写一条高质量记录，不写十条低质量记录
- Agent 写入不等于权威：06 目录内容仅作为参考，不能替代人工维护的 01-05 目录
- 审批是硬门控：优化建议未获人工确认前，不得修改任何业务目录内容
